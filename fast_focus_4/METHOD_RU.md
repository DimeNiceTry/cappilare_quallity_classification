# Устройство и развитие классификатора LR-4

## Задача и данные

Цель — быстро оценить пригодность кадра капилляроскопии для анализа сосудов. Хороший кадр должен показывать различимые границы мелких и крупных сосудов основной сети по полю изображения. Размытый глубокий фон допустим при чёткой основной сети. Значение `uncertain` описывает неуверенность разметчика, а не промежуточную степень резкости.

Исходный набор: 1000 кадров 1024×768, два кадра из каждого из 500 видео, 93 пациента. Бинарный набор после сравнения разметок: 62 `ok` и 503 `not_ok`; 435 спорных/неопределённых исключены. Согласие разметчиков не доказывает правильность: одна оценка историческая, другая получена при перекрёстном просмотре, критерии уточнялись. Отбор по согласию может оставлять более простые случаи.

## Расчёт четырёх входов

Вычисления соответствуют `focus_classifier/features.py`, версия `native-quality-v1`, `basic_only=True`. OpenCV декодирует исходный кадр в серый. Размер не меняется. Пусть `a = gray.astype(float32) / 255`, `s = GaussianBlur(a, sigmaX=1)`; размер ядра Gaussian выбирает OpenCV, стандартная обработка границ OpenCV сохранена.

1. **`laplacian_raw`**: `var(Laplacian(a, CV_32F, ksize=1))`.
2. **`laplacian_smooth`**: `var(Laplacian(s, CV_32F, ksize=1))`.
3. **`tenengrad_smooth`**: `mean(SobelX(s, ksize=3)^2 + SobelY(s, ksize=3)^2)`.
4. **`local_tenengrad_p75`**: карту энергии из пункта 3 делят на 4×4 равные области; находят среднюю энергию в каждой; берут 75-й процентиль 16 чисел (`numpy.percentile`, стандартная линейная интерполяция).

Здесь нет порога Sobel, автоматической обрезки, выделения сосудов и нейросети. Порядок четырёх признаков фиксирован списком `BASIC`. Зависимость от разрешения существенна: после уменьшения кадра числа означают другое, старые веса применять без проверки нельзя.

Лапласиан чувствителен к шуму; Tenengrad — к контрасту и количеству границ. p75 характеризует более контрастные/резкие части поля и может пропустить размытие других частей. Ни один вход непосредственно не проверяет различимость границ именно сосудов.

## Превращение признаков в оценку

Основной вариант `logistic_basic`:

```text
4 числа
→ log10(max(x, 1e-10))
→ StandardScaler, обученный на train
→ LogisticRegression(C=1, class_weight='balanced', max_iter=3000)
→ исходная P(ok)
→ sigmoid-калибровка logit исходной вероятности
→ откалиброванная P(ok)
→ сравнение с выбранным порогом
```

Калибратор — LogisticRegression с C=100, без balanced-весов. На вход подаётся logit вероятности, ограниченной диапазоном `[1e-6, 1-1e-6]`. Он обучается на внутренних OOF-прогнозах. Итоговая модель и калибратор не требуют PyTorch.

Сравнение `trees_basic`: ExtraTrees, 300 деревьев, `max_depth=10`, `min_samples_leaf=5`, `max_features=0.8`, `class_weight='balanced'`; на входе исходные четыре признака без логарифма и StandardScaler. Калибровка и правила порогов те же. При прогнозе используется один поток деревьев.

## Как получены метрики

Внешние части: `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=20261102)`, группа — пациент. Все кадры одного пациента остаются по одну сторону границы train/test. Список частей сохранён в `focus_classifier/artifacts/folds.json`.

Внутри каждого внешнего train три части по пациентам дают внутренние OOF-прогнозы. На них обучается sigmoid-калибратор и выбираются пороги. Один и тот же внутренний набор используется для этих двух операций; внешняя проверка остаётся отдельной. Затем классификатор обучается на всём внешнем train и оценивает внешний test. Во всех новых сравнениях сохраняем эти внешние части.

Обычный порог максимизирует balanced accuracy внутренних прогнозов. Строгий требует наблюдаемую precision ≥0,90 и минимум пять принятых внутренних кадров; среди подходящих вариантов выбирается сохраняющий больше хороших. Если подходящего порога нет, сохраняется служебное значение **2**, означающее отключённый автодопуск. Нельзя заменять это состояние утверждением «фотография плохая».

Метрики качества вычисляются на внешних OOF-прогнозах только 565 согласованных кадров. Итоговые веса для новых загрузок отдельно обучены на всех 565; проверка этих весов на тех же кадрах была бы обучающей оценкой. Известные фотографии обучения в третьем ноутбуке помечаются по SHA-256. Известность кадра в исходном наборе и его участие в обучении — разные флаги.

## Что показывают результаты

У LR-4 откалиброванный AUROC 0,880, AP 0,468. В обычном режиме приняты 53 из 62 хороших и 106 из 503 плохих: recall 85,5%, precision 33,3%. У ExtraTrees-4 соответственно 46 хороших и 77 плохих. Строгий режим отключён у обеих моделей. Поэтому нынешняя модель — исходная точка для ранжирования и улучшений; чистый автоматический допуск пока не получен.

ECE вероятности `ok` с десятью равными интервалами у LR уменьшается после калибровки с 0,211 до 0,041. Top-label ECE измеряет другую величину: согласованность уверенности в выбранном при 0,5 классе с правильностью этого класса. В ноутбуке показаны обе. ECE зависит от границ интервалов, числа кадров и распространённости классов; низкий ECE без precision/recall и PR недостаточен. Число хороших невелико, а в высоковероятностных интервалах особенно мало примеров.

У LR медиана старого замера PNG → решение около 63,5 мс, p95 140,8 мс на Intel i5-9300H. Классификация четырёх готовых чисел около 1 мс; чтение и признаки занимают большую часть задержки. Для видеопотока нужно отдельно мерить анализ уже декодированного кадра. Сравнение методов на одном CPU не гарантирует порядок скорости на другом.

## Что уже подготовлено для улучшения

В `02_reproduce_and_ablate_RU.ipynb` исходная LR-4 воспроизводится с проверкой совпадения всех внешних вероятностей и порогов с сохранёнными. Затем исключается каждый из четырёх признаков по одному, при неизменных модели, масштабе, калибровке и разбиении. Результаты лежат в `results/`; исходные веса не заменяются.

Парные интервалы разности AUROC получены 1000 повторными выборками пациентов для фиксированных OOF-прогнозов. Они не включают вариативность переобучения, не исправляют множественный выбор лучшего варианта и не заменяют независимый тест. Сравнение исключения признаков измеряет качество, а не ускорение: общий экстрактор пока всё равно вычисляет все четыре входа.

## Следующие эксперименты

1. Зафиксировать требуемые precision, recall и p95 задержки. Без них «лучше» может означать несовместимые режимы отбора.
2. Пересмотреть уверенные ложные допуски и потери хороших. Разделить очевидное размытие, шум, слабый контраст, неравномерный фокус и возможную ошибку разметки. Уточнения меток версионировать; при изменении набора пересчитать исходную модель на той же новой задаче.
3. На четырёх числах проверить регуляризацию LR и простые взаимодействия входов. Подбирать параметры только внутри внешнего train с группировкой пациентов; на внешней части не выбирать параметры или пороги.
4. Если модель над теми же входами исчерпана, отдельно проверить нормировку контраста/шума или изменение масштаба. Это новый вариант экстрактора: нужен пересчёт признаков, повторное обучение и новый замер времени. Не смешивать одновременно несколько изменений.
5. После фиксации метода получить отдельную съёмку с новыми пациентами и независимой разметкой. Проверить precision/recall, ROC/PR, ECE с числом кадров в интервалах, примеры ошибок и скорость. Данные для финальной проверки не использовать для очередного выбора модели.

Без разметки сосудов или результатов их измерения мы оцениваем согласие с визуальной меткой пригодности, а не точность последующей сегментации/диаметров.
